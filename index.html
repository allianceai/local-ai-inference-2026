State of Local AI Inference 2026

Intelligence Package — August 2026

Executive Summary

Mid-2026 is the inflection point where running serious AI locally stopped being a hobbyist pursuit and became a legitimate production strategy. The open-weight model ecosystem has matured dramatically: you can run a 32-billion-parameter model on a MacBook Pro, hit 150+ tokens per second on a consumer GPU with the right runtime, and make meaningful quality-vs-speed tradeoffs through quantization formats that have stabilized around a handful of proven standards.

Three hardware stories dominate: Apple Silicon’s M3/M4 generation with unified memory pools up to 128GB, NVIDIA’s RTX 40/50-series with dedicated VRAM and GPU-optimized inference stacks, and AMD’s surprise entrant — the Strix Halo architecture (Ryzen AI Max+ 395) that benchmarks faster than Apple M3 Max at a fraction of the price in some configurations. The days of “local AI is too slow” are over. The question now is which combination of model, runtime, quantization, and hardware fits your workload.

Model Landscape

Five model families own the open-weight space heading into mid-2026.

Llama 3.1/3.3 (Meta) remains the reference architecture. The 8B variant is the benchmark baseline every runtime targets first, delivering 53.5 tok/s on M3 Max via llama.cpp and a remarkable 170 tok/s on AMD Strix Halo. The 70B model — accessible via multi-GPU vLLM or large unified-memory Macs — represents the ceiling of what consumer hardware can run without cloud augmentation. Llama 3.3 70B at GPTQ quantization on dual RTX 4090s delivers 40 tok/s, genuinely usable for batch inference.

Qwen2.5 (Alibaba) is the sleeper hit. The 7B coder variant punches above its weight class in coding tasks, while the 32B model balances capability and hardware fit better than most competitors — landing at 20GB in Q4_K_M with 14 tok/s on M3 Max or a blistering 101 tok/s on Strix Halo. Qwen2.5 72B via MLX 4-bit on a 128GB Mac runs at 7.5–10.5 tok/s: too slow for interactive use but viable for batch jobs and RAG pipelines with caching.

Gemma 3 (Google) introduced a 27B model that holds the sweet spot for Apple Silicon users: fits in 16GB at MLX 4-bit quantization and runs at 19–26 tok/s depending on M3 or M4 Max — a real 37% generational jump. The 12B variant is the workhorse for users with 16–24GB unified memory.

Mistral Small 24B is the strongest all-around local model in 2026. It consistently delivers GPT-4-class reasoning across diverse tasks while fitting in 14GB at Q4 quantization — leaving headroom for context and system overhead on both Mac and NVIDIA platforms. On RTX hardware with vLLM, it hits 62.5 tok/s on a single 4090 and 115 tok/s on the 5090.

DeepSeek-R1-Distill variants rewrote expectations for reasoning tasks. The 7B distill at GPTQ on a single RTX 4090 delivers 110 tok/s with chain-of-thought reasoning — outperforming models twice its size on math and coding benchmarks. The 32B distill is the reasoning ceiling for 24GB GPUs: AWQ puts it at 20GB VRAM utilization, leaving room for inference at 32.5 tok/s on a 4090, and scaling to 90 tok/s on the 5090.

Runtime Comparison

llama.cpp is the universal baseline — cross-platform, CPU+GPU hybrid, and first to support new GGUF quantization variants. Peak performance: 53.5 tok/s on M3 Max for Llama 8B. Where it excels: maximum hardware compatibility, quantization breadth, and offline-first deployments. Where it lags: throughput ceiling is lower than GPU-optimized runtimes; primarily single-user focused.

Ollama wraps llama.cpp in a Docker-like model management layer with a local REST API. The throughput penalty vs raw llama.cpp is modest (46.2 vs 53.5 tok/s on M3 Max for Llama 8B) but the developer experience is dramatically better: ollama run qwen2.5:32b and you’re running within minutes. It’s the default choice for local development and single-user workflows.

vLLM is the GPU throughput winner, and it isn’t close. Mistral 7B AWQ on a single RTX 4090 delivers 150 tok/s — roughly 3× what Ollama achieves on Apple Silicon for the same model class. The 5090 pushes that to 232.5 tok/s. vLLM’s continuous batching and PagedAttention make it the right call for multi-user inference servers or any workload where latency matters. Requires CUDA; no Apple Silicon support.

MLX is Apple’s answer to vLLM for M-series chips. The framework uses Metal’s unified memory architecture to co-locate weights and compute in a way llama.cpp can’t fully exploit. MLX is the correct runtime for any Mac with 32GB+ unified memory running models above 13B parameters — the 4-bit MLX quantization consistently beats GGUF Q4_K_M in throughput on the same hardware.

ONNX Runtime covers edge deployment, mobile quantization, and cross-platform compatibility. Throughput lags GPU-native runtimes significantly for large models, but if you’re shipping inference to end-user hardware you don’t control, ONNX is the standard. It’s the runtime for applications, not inference servers.

Quantization Tradeoffs

GGUF (GGML Unified Format) is the universal container for llama.cpp and Ollama. The Q4_K_M variant is the community sweet spot: roughly 4.5 bits per weight, ~5–8% quality loss vs full precision, universally supported across every platform. Q8 gives near-lossless quality at double the RAM cost; Q2 is aggressive compression that noticeably degrades reasoning on complex tasks.

AWQ (Activation-Aware Weight Quantization) targets CUDA runtimes. It applies 4-bit quantization more intelligently than naive rounding by identifying salient weights, preserving quality while achieving the same memory footprint as Q4_K_M. AWQ is the format to use with vLLM on NVIDIA hardware — pre-quantized models are abundant on Hugging Face for all major model families.

GPTQ is the mature GPU quantization standard, still well-supported by vLLM and ExLlamaV2. Quality is slightly behind AWQ at the same bit-depth for most families, but tooling is mature and GPTQ models appear within days of any major release. The 4090’s strong FP16 tensor core performance makes GPTQ more competitive here than on older NVIDIA generations.

MLX 4-bit is Apple-proprietary but the Metal-aware implementation outperforms GGUF Q4 on the same Apple Silicon hardware for mid-to-large models. If you’re on an M-series Mac, pull MLX variants from the mlx-community Hugging Face org rather than GGUF when running anything above 13B parameters. The quality-per-gigabyte is measurably better.

Hardware Price/Performance

Apple M3/M4 (M-series) unified memory architecture is the defining hardware story of 2026 for consumer local AI. A 32GB MacBook Pro M4 runs Mistral 24B class models comfortably; a 64GB Mac Studio M4 Max handles 70B quantized models; the 128GB Mac Studio ceiling can run Qwen2.5 72B and Llama 70B at usable speeds. Pricing: $2,000–$4,200. Key limitation: no CUDA, so vLLM and all CUDA-optimized inference stacks are off the table.

NVIDIA RTX 40/50-series is the throughput choice. A single RTX 4090 (24GB VRAM, ~$1,800–$2,200 used) running vLLM with AWQ quantization delivers 3–5× the tokens-per-second of equivalent Apple Silicon for 7–24B models. The RTX 5090 (32GB VRAM) extends the envelope to 32B models on a single card and pushes Mistral 7B to 232.5 tok/s. For production inference servers, a dual-4090 or single-5090 workstation ($3,800–$9,500 all-in) outperforms Mac Studio on throughput per dollar at scale.

AMD Strix Halo (Ryzen AI Max+ 395) is the unexpected contender of 2026. Laptops with the Max+ 395 and 128GB unified memory hit 170 tok/s on Llama 3.1 8B — faster than the M3 Max on identical models. More striking: Qwen2.5 32B at Q4_K_M runs at 101 tok/s on Strix Halo vs 14 tok/s on M3 Max 64GB. At $2,799–$3,200 for top-configured laptops (ASUS ROG, Lenovo Legion), this is the highest tokens-per-dollar value in 2026 for mid-size model inference, with the portability of a laptop.

What I'd Run Today

32GB Mac: Mistral Small 24B via Ollama with MLX 4-bit quantization. Run ollama run mistral-small and it settles into approximately 14GB unified memory, leaving 18GB for the OS, context window, and concurrent processes. You’ll see 22–30 tok/s depending on chip generation — fast enough for interactive coding assistance, writing, and research. If your primary use case is math or code reasoning specifically, swap to DeepSeek-R1-Distill-Qwen-14B via GGUF Q4_K_M: 9GB footprint, runs on any Mac, and the chain-of-thought output quality is exceptional for the hardware cost.

24GB NVIDIA GPU: Mistral Small 24B via vLLM with AWQ quantization. Install vLLM, pull a pre-quantized AWQ variant from Hugging Face, and serve it: vllm serve --model mistralai/Mistral-Small-24B-Instruct-AWQ. You’ll hit 60–65 tok/s on a single 4090, VRAM usage lands at 14GB with comfortable headroom, and Mistral Small’s instruction-following is strong enough that the quality gap vs cloud APIs is negligible for most workflows. If throughput matters above all else and quality can be 7B-class, the DeepSeek-R1-Distill-Qwen-7B at GPTQ is the speed champion: 110 tok/s on only 5.5GB VRAM.
